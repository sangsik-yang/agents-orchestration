02 / Architecture

Supervisor 중심의 폐루프 실행 구조

worker는 직접 다음 단계를 결정하지 않습니다. 모든 worker 결과는 Supervisor로 돌아가며, Supervisor가 다음 action 또는 FINISH를 결정합니다.

Input Layer

User / CLI

Interactive 입력, smoke query, custom `--query`를 받아 fresh state에 HumanMessage로 추가합니다.

Control Plane

Supervisor

라우팅, 오류 분석, retry limit, finalization 판단을 담당합니다. 출력은 `{ next, instruction }` JSON 계약입니다.

Shared State

AgentState

messages, next, data, retry_count, last_error를 보관합니다. data는 worker 간 명시적 공유 메모리입니다.

STARTStateGraph가 Supervisor로 진입
ROUTESupervisor가 worker 선택
WORKResearcher / SQLQueryer / Writer 실행
STORE결과를 messages/data에 누적
REVIEWSupervisor가 다음 단계 판단
FINISHWriter 응답 후 종료
03 / Implementation Map

코드 모듈별 책임

관심사가 비교적 잘 분리되어 있습니다. main은 graph/run loop, agents는 worker logic, runtime_controls는 observability와 throttle을 담당합니다.

Worker Stack

Researcher DuckDuckGo search tool을 가진 ReAct agent. `search_history`를 shared data에 누적.
SQLQueryer `sqlite:///titanic.db`에 연결하는 LangChain SQL agent. 결과와 실행 SQL을 data에 저장.
Writer shared data를 JSON context로 주입받아 최종 요약과 보고서를 합성.

Key Files

  • `main.py`: LLM 생성, graph assemble, CLI args, stream 처리.
  • `state.py`: `AgentState` typed state 계약.
  • `agents/supervisor.py`: 라우팅 prompt, JSON parsing, content normalization.
  • `runtime_controls.py`: LLM/tool callback logging, API delay throttle.
  • `logger.py`: colorlog 기반 중앙 로깅.
  • `tests/`: graph entry, node behavior, runtime controls regression tests.
04 / Validation

현재 검증 상태와 남은 리스크

단위 테스트는 통과했지만, 외부 API와 웹 검색, LangSmith tracing은 네트워크 조건에 영향을 받습니다.

Verified Today

  • 명령: `.venv/bin/python -m pytest -q`
  • 결과: `32 passed`
  • 실제 무료 API 실행: Titanic 여성 314명 중 233명 생존, 생존율 74.2%. Writer 요약과 FINISH 성공.
  • 검증 범위: smoke mode, non-interactive loop, supervisor routing, list content normalization.
  • 검증 범위: researcher/writer/sql worker runtime config 전달, API throttle callback.

Operational Risks

  • OpenRouter API key와 네트워크 연결 없이는 실제 LLM 실행 불가.
  • DuckDuckGo 검색 worker는 외부 서비스 상태와 rate limit에 영향.
  • `titanic.db`가 준비되지 않으면 SQLQueryer의 실제 분석 경로 실패 가능.
  • LangSmith 시작 시 연결 실패는 추적 없이 계속 실행. 실행 중 전송 실패는 SDK 정책을 따름.
05 / Roadmap

앞으로의 개발 계획

다음 단계는 데모 완성도가 아니라 운영 안정성과 사용성 확장에 우선순위를 두는 것이 합리적입니다.

Observability Fallback

시작 시 LangSmith 연결 실패 fallback 완료. 다음 단계는 실행 중 연결 단절 시 SDK 재시도 정책 보완입니다.

Data Source Expansion

SQLite Titanic 예제에서 벗어나 Notion, Slack, Google Drive, 내부 DB 등 실제 업무 데이터 소스를 연결합니다.

Web UI Layer

현재 CLI 실행을 Streamlit/FastAPI 기반 UI로 확장해 실행 로그, shared memory, worker decision을 시각화합니다.

Session Persistence

다중 사용자와 장기 task를 위해 state checkpoint, conversation persistence, per-session config를 도입합니다.

Evaluation Harness

고정 질의 세트와 expected behavior를 정의해 routing 품질, SQL 정확도, writer faithfulness를 회귀 검증합니다.

Tool Safety Policy

worker별 tool permission, query allowlist, retry budget, failure escalation 정책을 명시적으로 분리합니다.
